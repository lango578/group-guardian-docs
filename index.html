1. 架构总览

┌─────────────────────┐   双向同步(启动+每10分钟)   ┌─────────────────────┐
│  QQ 群机器人服务器     │ ──────────────────────────▶ │    后台服务端服务器     │
│  群守护者插件 v2.36.8 │ push: 误判复盘/已确认违规/   │  Flask + SQLite        │
│  （群内审核/撤回/禁言）│      审核信息上传             │  宝塔部署              │
│                      │ ◀────────────────────────── │  多用户(owner/admin/   │
└─────────────────────┘  pull: 拉取写回 + 执行管理员动作 │   member) + Web 看板   │
                                                      └─────────────────────┘
  • 插件：跑在 AstrBot 机器人所在机器，负责群内一切审核与处罚动作（文本 / 图片 / 视频 / 群名片）。
  • 服务端（本教程部署对象）：独立部署在另一台服务器（或同台），集中保存数据、提供多人查看 / 操作界面。
  • 两者通过 HTTP API 双向同步，插件配置好 sync_server_* 后自动工作，换服务器数据不丢。

2. 部署前准备

项目要求
服务器一台可访问公网的 Linux 服务器（腾讯云 / 阿里云 / 华为云等均可，1 核 1G 起步即可）
系统CentOS 7+ / Ubuntu 20.04+ / Debian 10+
宝塔面板7.7+（本教程以宝塔「Python 项目管理器」为例）
Python3.10+（用宝塔安装，见第 4 节）
域名推荐有（用于 HTTPS，避免 QQ / 微信外链拦截）；没有可用 IP 直连
端口默认 9000（可改），需在宝塔防火墙与云安全组放行
如果只是本机 / 内网测试：pip install -r requirements.txt 后 python app.py， 浏览器打开 http://127.0.0.1:9000 即可，无需服务器与域名。

3. 上传服务端文件

服务端压缩包 gg_server.zip 解压后的目录内容如下：

gg_server/
  app.py                 # 服务端主程序（API + 后台 + /docs 教程 + /appeal 申诉页）
  requirements.txt       # 依赖清单（flask）
  templates/index.html   # 后台管理页面
  templates/appeal.html  # 公开申诉页（发给群成员）
  templates/docs.html    # 在线教程页
  update_source.json     # （可选）OTA 更新源配置
  data/                  # 运行时自动生成（SQLite 数据库 server.db），备份它即可迁移
1
登录宝塔面板 → 文件 → 进入 /www/wwwroot/（或任意目录）→ 上传 gg_server.zip。
2
右键压缩包 → 解压，得到 gg_server/ 目录。
3
确认 app.py 在 /www/wwwroot/gg_server/ 下，不要多套一层目录。
若你在本机已有该目录，也可以用命令行上传：
scp -r gg_server root@你的服务器IP:/www/wwwroot/

5. 创建项目并启动服务端

端口说明（重要）：宝塔「Python 项目管理器」分新旧两版，创建界面不同——
① 旧版 1.x（界面里有「监听端口」框）：直接在「监听端口」填 9000；
② 新版 2.x（没有端口输入框）：在「启动参数」填 9000（或 --port 9000）；留空则默认监听 9000。
反向代理目标写 http://127.0.0.1:9000 即可，只要服务端监听端口与反向代理目标一致。
1
宝塔 → Python 项目管理器 → 添加项目，按下表填写：
项填什么
项目名称随意，如 gg_server
项目路径/www/wwwroot/gg_server
Python 版本选刚安装的 3.10+
启动方式框架（Flask）
启动文件app.py（默认即可）
监听端口旧版填 9000；新版没有此框 → 跳过
启动参数新版可填 9000 或 --port 9000；留空则默认 9000
2
添加后项目会自动执行 pip install -r requirements.txt 安装依赖；若没自动装，点项目 → 依赖管理，或手动执行：
cd /www/wwwroot/gg_server
pip install -r requirements.txt
3
点 启动。项目状态变为「运行中」即成功。

6. 验证服务端是否正常

在服务器命令行执行：

curl -I http://127.0.0.1:9000/
返回 HTTP/1.1 200 OK → 服务端已在运行。若改了端口（如 9001），把测试地址与反向代理目标同步改成对应端口。

也可以直接看日志文件（最可靠，不依赖宝塔面板日志）：

tail -50 /www/wwwroot/gg_server/server.log

出现 [gg_server] 群守护者后台服务端已启动 横幅与 Running on all addresses (0.0.0.0) 即正常。

7. 域名 + 反向代理 + HTTPS（推荐）

只用 IP 访问可跳过本节；但推荐配置域名，用 80 / 443 端口更稳定，QQ / 微信里打开外链也不会被拦截。
1
域名解析：到域名服务商后台，添加 A 记录指向你的服务器公网 IP。
2
宝塔 → 网站 → 添加站点：域名填 gg.example.com（换成你的），其它默认，提交。
3
进入该站点 → 反向代理 → 添加反向代理：
项填什么
代理名称gg_server
目标 URLhttp://127.0.0.1:9000
4
开启 HTTPS（推荐）：站点 → SSL → Let's Encrypt → 选择域名申请证书并开启「强制 HTTPS」。
5
浏览器打开 https://你的域名 → 出现注册页即部署成功。
返回目录 ↑

8. 防火墙与云安全组放行

如果要用 IP + 9000 端口直连访问，需要放行 两处（缺一不可）：

1
宝塔防火墙：宝塔 → 安全 → 放行端口 9000（TCP）。
2
云安全组：云服务器控制台 → 安全组 → 入方向规则 → 放行 TCP 9000，来源 0.0.0.0/0，并确认实例已关联该安全组。

放行后在外网机器验证：

telnet 你的服务器IP 9000
强烈建议改用 80 / 443 + 域名反向代理：非常用端口更容易被运营商 / 云环境干扰。最稳的访问方式是第 7 节方案，此时云安全组只需放行 80 / 443。

9. 注册首个管理员账号

1
浏览器打开后台地址：https://你的域名/（或 http://IP:9000/）。
2
点「首次使用？注册」→ 填写用户名 + 密码（至少 6 位）。
3
第一个注册的账号自动成为 owner（所有者，拥有全部权限）；注册后即自动登录进入后台。
注册通道只在尚无任何用户时开放。之后新账号由 owner / admin 在「用户管理」中创建。
登录后默认进入「误判复盘」页：顶部有 5 张统计卡片，左侧 7 个导航标签（误判复盘 / 已确认违规 / 误封申诉 / 修正建议 / 待执行动作 / 系统更新 / 用户管理）。

10. 插件端接入与云同步

在 AstrBot 的 群守护者插件配置（_conf_schema.json 中相关项）里填写以下内容：

配置项填什么
sync_server_urlhttps://你的域名（或 http://IP:9000）
sync_username后台注册的账号（如 owner）
sync_password对应密码
sync_auto开（启动 + 每 10 分钟自动双向同步）
1
保存配置并重启 AstrBot / 插件。
2
插件启动时会自动 push：误判复盘 / 已确认违规 / 修正建议上传到服务端。
3
刷新后台页面 → 各表格出现插件同步的数据即接入成功。
换服务器快速恢复：新机器装好插件并填同样的 sync_server_* 后重启，插件自动 pull 回全部云端数据，无需手动搬运。

11. 多用户与权限

角色权限
普通成员 member查看全部数据（误判复盘 / 已确认违规 / 申诉列表）
管理员 admin查看 + 确认违规 / 放行 / 标记误封解禁 / 审核申诉 + 创建用户
所有者 owner全部权限 + 用户管理（创建 / 删除用户）

创建方式：owner / admin 登录后 → 左侧「用户管理」→ 输入用户名 / 密码 / 选择角色 → 创建。

普通成员登录后只读查看，不显示任何操作按钮；管理员操作都会生成待执行动作，由插件下次同步执行。

12. 误封申诉 / 解禁通道

被处罚用户可以提交误封申诉，管理员审核通过后插件自动解除禁言：

1
用户提交（两种方式任选）：
① 打开公开申诉页 https://你的域名/appeal —— 无需登录、不含任何后台功能，可以直接把这个链接发给群成员，填 QQ 号 + 群号（可选）+ 申诉理由提交；
② 或登录后台，在「误封申诉 / 解禁」页顶部表单提交。
2
管理员审核：后台「误封申诉」页看到 pending 申诉 → 点「通过并解禁」或「驳回」；也可在「已确认违规」页直接点「标记误封解禁」。
3
自动解禁：服务端生成 unban 动作 → 插件下次同步执行 set_group_ban(duration=0) 解除禁言并记录日志。
公开申诉页防刷：同一 IP 10 分钟内最多提交 3 次（超限返回 429）。开关：app.py 顶部 PUBLIC_APPEAL_OPEN = True，改为 False 即关闭公开页（后台提交不受影响）。

13. 数据备份与换服务器迁移

1
备份：只需备份 /www/wwwroot/gg_server/data/ 整个目录（内含 SQLite 数据库 server.db）。建议定期整目录下载 / 复制。
2
迁移：新机器按第 3 ~ 5 节部署服务端，然后把旧机的 data/ 目录覆盖到新机同名位置。
3
重启服务端 → 数据（账号 / 误判复盘 / 违规 / 申诉 / 待执行动作）全部恢复。
4
插件端：新机器装好插件、填同样的 sync_server_* 后重启，自动 pull 写回本地数据。
服务器换 IP / 换域名时，只需更新插件配置里的 sync_server_url，数据库无需改动。

14. 升级与更新

方式一：OTA 在线更新（v1.1.0+）

1
在 gg_server/update_source.json 填版本清单地址：
{ "url": "https://你的域名/版本清单.json" }
2
版本清单 JSON（放在可公网访问的位置）格式：
{ "version": "1.2.0", "notes": "新增功能", "zip_url": "https://你的域名/gg_server_1.2.0.zip" }
3
后台「系统更新」页 → 查看当前 / 最新版本 → 点「应用服务器端更新」：自动下载 zip → 解压覆盖代码（自动备份到 backup_时间戳/，保留 data/ 与 update_source.json）。
4
更新完成后手动重启服务端生效。

方式二：手动覆盖更新

1
停止服务端 → 上传新版 zip 覆盖（保留 data/ 目录）→ 重启。
更新包 zip 内需包含 app.py（顶层或任意子目录均可），版本号写在清单的 version。

15. 常见问题排查

Q1：日志是空的？

新版服务端会写文件日志 server.log：① 先 tail -50 /www/wwwroot/gg_server/server.log —— 有启动横幅说明服务正常（只是宝塔面板日志显示问题）；没有该文件说明服务没启动；② 看项目管理器里项目是否「运行中」；③ 确认依赖 pip install -r requirements.txt；④ 手动 python -u app.py 看输出；⑤ 启动命令可加 -u 无缓冲实时刷日志。

Q2：端口开了还是连不上？

按顺序排查：① ss -lntp | grep 9000 看是否 0.0.0.0:9000 监听（若是 127.0.0.1 说明只监听本机，检查启动方式 / gunicorn 需 -b 0.0.0.0:9000）；② 本机 curl -I http://127.0.0.1:9000/ 通、公网不通 = 公网入口问题；③ 宝塔「安全」放行 9000 并 firewall-cmd --reload；④ 云控制台安全组入方向放行 TCP 9000、来源 0.0.0.0/0，实例已关联；⑤ 另一台机器 telnet 你的IP 9000；⑥ 最稳：用域名 + 80/443 反向代理。

Q3：出现 ModuleNotFoundError: flask？

依赖没装到当前 Python：在项目目录手动执行 pip install -r requirements.txt；或在宝塔项目管理器里确认「依赖管理」列表有 flask，且项目使用的 Python 版本与安装依赖的一致。

Q4：出现 Address already in use？

端口被占用。换一个端口（如 9001）并把反向代理目标同步修改；或杀掉占用进程：ss -lntp | grep 9000 找到 PID → kill PID。

Q5：反向代理后页面打开是 502 / 404？

① 确认服务端在运行且监听端口与反向代理「目标 URL」一致；② 反向代理目标写 http://127.0.0.1:9000（不要写成公网地址）；③ 若改了端口，目标 URL 要同步改。

Q6：忘记管理员密码？

删除 data/server.db 后重新注册首个账号（会清空云端数据，谨慎操作）。

Q7：插件同步不生效？

① 确认插件配置的 sync_server_url 可公网访问（浏览器能打开）；② 确认用户名 / 密码正确；③ 看插件日志是否有 401 / 403；④ 确认 sync_auto 开启并重启插件。

Q8：公开申诉页 429？

同一 IP 10 分钟内提交超过 3 次会限流，等待 10 分钟后再试。
