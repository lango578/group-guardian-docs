# 群守护者 · 后台服务端 —— 详细部署教程

> 与 QQ群智能守护者插件分离的独立 Web 服务：集中保存 **AI 误判复盘 / 修正规则建议 /
> 已确认违规 / 审核信息**，支持多用户权限（成员只读、管理员可操作），插件双向同步，
> 换服务器数据不丢。部署后打开 `http://域名/docs` 可在线查看图文教程。

---

## 0. 整体架构（先看这张图）

```
┌────────────────────┐        双向同步(启动+每10分钟)         ┌────────────────────┐
│  QQ 群机器人服务器    │  ──────────────────────────────────▶ │   后台服务端服务器     │
│  群守护者插件 v2.36.8 │  push: 误判复盘/已确认违规/审核信息上传   │  Flask + SQLite      │
│  （群内审核/撤回/禁言） │  ◀────────────────────────────────── │  宝塔部署             │
│                    │  pull: 缺的数据拉取写回 + 执行管理员操作    │  多用户(owner/admin/  │
└────────────────────┘                                          │   member) + Web看板  │
                                                                └────────────────────┘
```

- **插件**：跑在 AstrBot 机器人所在机器，负责群内一切审核与处罚动作。
- **服务端**（本教程部署对象）：独立部署在另一台服务器（或同台也可以），集中保存数据、
  提供多人查看/操作界面。
- 两者通过 HTTP API 同步，插件配置好 `sync_server_*` 后自动工作。

## 1. 环境要求

| 项目 | 要求 |
|---|---|
| 服务器 | 一台可访问公网的 Linux 服务器（腾讯云/阿里云/华为云等均可，1 核 1G 起步即可） |
| 系统 | CentOS 7+ / Ubuntu 20.04+ / Debian 10+ |
| 宝塔面板 | 7.7+（本教程以宝塔「Python 项目管理器」为例） |
| Python | 3.10+（宝塔安装） |
| 域名 | 推荐有（用于 HTTPS，避免微信/QQ 外链拦截）；没有可用 IP 直连 |
| 端口 | 默认 9000（可改）；需在宝塔防火墙与云安全组放行 |

## 2. 准备服务端文件

本地目录 `gg_server/` 内容如下：

```
gg_server/
  app.py                 # 服务端主程序（API + 前端 + /docs 教程）
  requirements.txt       # 依赖：flask
  templates/index.html   # 后台管理页面
  templates/docs.html    # 在线部署教程页
  data/                  # 运行时自动生成（SQLite 数据库 server.db），备份它即可迁移
```

上传到服务器任意目录，**推荐** `/www/wwwroot/gg_server`：

```
# 方式一：宝塔「文件」→ 上传 → 解压
# 方式二：服务器命令行（本机已有该目录时）
scp -r gg_server root@你的服务器IP:/www/wwwroot/
```

> 上传后确认 `gg_server/app.py` 在 `/www/wwwroot/gg_server/` 下（不要多套一层目录）。

## 3. 安装 Python 环境（宝塔）

1. 登录宝塔面板 → 左侧 **软件商店**；
2. 搜索 **Python 项目管理器** → 点击 **安装**；
   - 若商店没有，可先安装 **Python 项目管理器 2.x**（宝塔插件）。
3. 安装完成后进入 **Python 项目管理器** → **Python 版本** → 添加一个 **3.10+** 版本
   （如 3.10.14 / 3.12），等待编译/下载完成。

> 也可以用系统自带 Python 3.10+：`python3 --version` 确认即可，后续用 `python3` 命令。

---

## 4. 创建项目并启动服务端

> ⚠️ **端口说明（重要）**：宝塔「Python 项目管理器」分新旧两个版本，创建界面不一样：
> - **旧版（1.x，界面里有「监听端口」框）**：直接在「监听端口」填 `9000`；
> - **新版（2.x，没有端口输入框）**：在「启动参数」填 `9000`（或 `--port 9000`）；
>   如果「启动参数」留空，服务端**默认监听 9000**，反向代理目标写
>   `http://127.0.0.1:9000` 即可（端口不重要，只要服务端监听端口和反向代理目标一致）。

1. 宝塔 → **Python 项目管理器** → **添加项目**，按下面填：

| 项 | 填什么 |
|---|---|
| 项目名称 | 随意，如 `gg_server` |
| 项目路径 | `/www/wwwroot/gg_server` |
| Python 版本 | 选刚安装的 3.10+ |
| 启动方式 | 框架（Flask） |
| 启动文件 | `app.py`（默认即可） |
| 监听端口 | 旧版填 `9000`；**新版没有此框 → 跳过** |
| 启动参数 | 新版可填 `9000` 或 `--port 9000`；留空则默认 9000 |

2. 添加后，项目自动执行 `pip install -r requirements.txt` 安装依赖；
   若没自动装，点项目 → **依赖管理**，或手动：
   ```
   cd /www/wwwroot/gg_server
   pip install -r requirements.txt
   ```

3. 点 **启动**。日志出现 `Running on all addresses (0.0.0.0)` 即成功。

4. **测试**（在服务器上）：
   ```
   curl -I http://127.0.0.1:9000/
   ```
   返回 `200 OK` 表示服务端已在运行。若改了端口（如 9001），把测试和反向代理
   目标都改成对应端口。

## 5. 配置域名 + 反向代理 + HTTPS（推荐）

> 如果只用 IP 访问，可跳过本节，直接到第 6 节。

1. 宝塔 → **网站** → **添加站点**：
   - 域名填你的域名（如 `gg.example.com`）；
   - 其它默认，提交。
2. 进入该站点 → **反向代理** → **添加反向代理**：
   - 代理名称：`gg_server`
   - 目标 URL：`http://127.0.0.1:9000`
   - 提交。
3. 开启 HTTPS（可选，推荐）：
   - 站点 → **SSL** → Let's Encrypt → 申请并部署，开启「强制 HTTPS」。
4. 浏览器访问 `https://gg.example.com` 应看到登录页；
   `https://gg.example.com/docs` 是在线部署教程。

## 6. 防火墙与安全组（重要）

部署后打不开页面，多半是端口没放行：

1. **宝塔防火墙**：宝塔 → **安全** → 放行端口 `9000`（或你改的端口）；
2. **云厂商安全组**：登录云控制台（腾讯云/阿里云等）→ 安全组 → 入方向放行 TCP `9000`（或 `80/443` 如果走了站点反向代理）；
3. 验证：
   ```
   curl -I http://你的IP:9000/
   ```
   能返回 `200` 即公网可达。

> 若走了「域名 + 反向代理 + HTTPS」，只需放行 `80/443`，`9000` 可只在宝塔放行（代理本机访问）。

## 7. 首次使用（注册与建号）

1. 浏览器打开 `http://你的域名`（或 `http://IP:9000`）；
2. 点「**首次使用？注册**」→ 输入用户名 + 密码（≥6 位）→ 注册。**第一个账号自动成为 owner**；
3. 注册后进入面板：
   - 顶部可看统计数据；左侧标签可切「误判复盘 / 已确认违规 / 修正建议 / 待执行动作 / 用户管理」；
   - 在「**用户管理**」创建：
     - **admin**：给插件同步用（也拥有确认/放行权限）；
     - **member**：给普通成员（只读查看）；
4. 打开 `http://你的域名/docs` 可随时查看本教程。

## 8. 插件对接（让机器人自动同步）

1. AstrBot 上传安装插件 `astrbot_plugin_group_guardian-v2.36.8.zip`（或更高）；
2. 插件 WebUI → **设置** → 找到「云同步」配置：

| 配置项 | 填什么 | 示例 |
|---|---|---|
| `sync_server_url` | 服务端地址 | `http://你的域名` 或 `http://1.2.3.4:9000` |
| `sync_username` | 服务端管理员账号 | `admin1` |
| `sync_password` | 对应密码 | `********` |
| `sync_auto` | 开启自动同步 | `true` |
| `sync_interval` | 同步周期（分钟） | `10` |

3. 保存 → 重启插件。日志出现：
   - `云同步上传完成: feedback=… suggestions=… violations=…`
   - `云同步拉取完成: feedback=… violations=…`
   即同步成功。

> 插件同步用的是管理员账号（owner/admin）；member 账号只在后台网页只读查看。

## 9. 数据备份与迁移

- **备份**：复制整个 `gg_server/data/` 目录即可（内含 `server.db`）。
  建议每日定时备份：宝塔 → **计划任务** → Shell 脚本：
  ```bash
  cp -r /www/wwwroot/gg_server/data /www/backup/gg_server_data_$(date +%Y%m%d)
  ```
- **迁移到新服务器**：新服务器装好服务端后，把旧 `data/` 目录覆盖过去，重启即可；
- **插件侧恢复**：新机器人装插件 → 填同样的 `sync_server_url / sync_username / sync_password`
  + `sync_auto` 开 → 启动即自动 pull 回误判复盘 / 已确认违规 / 审核信息。

## 10. 生产化建议（gunicorn + 守护）

Flask 自带 server 仅供开发；生产建议用 gunicorn + supervisor：

```bash
pip install gunicorn
cd /www/wwwroot/gg_server
gunicorn -w 2 -b 127.0.0.1:9000 app:app --daemon
```

宝塔 → 软件商店 → **Supervisor 管理器** 添加守护进程（可选）：
- 启动命令：`gunicorn -w 2 -b 127.0.0.1:9000 app:app`
- 运行目录：`/www/wwwroot/gg_server`
- Python 解释器：选项目 Python 环境的 python

## 11. 常见问题

| 现象 | 排查 / 解决 |
|---|---|
| 页面打不开 | ① 服务是否启动（日志） ② 宝塔防火墙放行端口 ③ 云安全组放行 ④ 反向代理目标端口是否一致 |
| 反向代理 502 | 目标地址写成 `http://127.0.0.1:9000`（不要写域名）；确认 9000 服务在运行 |
| 插件同步失败 | ① 服务端地址可访问（`curl http://域名/`） ② 账号密码正确（owner/admin） ③ 服务端日志无报错 |
| 忘记管理员密码 | 删除 `gg_server/data/server.db` 后重新注册首个账号（会清空云端数据，谨慎） |
| 端口被占用 | `lsof -i:9000` 找到进程；或改 `PORT` 环境变量换端口并同步改反向代理 |
| **项目管理器日志是空的** | 看下方「日志为空怎么办」 |

## 附：端口开了还是连不上（排查顺序）

公网连不上 `http://你的IP:9000`，按下面顺序逐项排查（**别跳步**）：

### 1. 确认服务真的在监听（并监听在 0.0.0.0）
```bash
ss -lntp | grep 9000
# 或 netstat -lntp | grep 9000
```
- 期望输出：`0.0.0.0:9000  LISTEN`（`0.0.0.0` 表示所有网卡）。
- 如果显示 `127.0.0.1:9000`：服务只监听本机，公网当然连不上。
  - 直接跑 Flask：确认 `app.run(host="0.0.0.0", ...)`（本项目的 app.py 已如此）；
  - 用 gunicorn：绑定要写 `-b 0.0.0.0:9000`（教程第 10 节的 `-b 127.0.0.1:9000`
    只适用于「有 Nginx 反向代理」的场景）。
- 如果完全没有 9000 的行：服务没起来（回到「日志为空怎么办」）。

### 2. 从服务器本机自测（区分「服务问题」还是「网络问题」）
```bash
curl -I http://127.0.0.1:9000/          # 本机回环
curl -I http://你的内网IP:9000/          # 本机内网
curl -I http://你的公网IP:9000/          # 本机访问公网IP
```
- 前两条通、最后一条不通 → **公网入口问题**（安全组/防火墙/云厂商）；
- 三条都不通 → **服务本身没起来**。

### 3. 宝塔防火墙
宝塔 → **安全** → 确认 `9000` 在「已放行端口」列表。若仍不行，在服务器命令行强制放行并重载：
```bash
# CentOS 7+ (firewalld)
firewall-cmd --permanent --add-port=9000/tcp
firewall-cmd --reload
# Ubuntu/Debian (ufw)
ufw allow 9000/tcp
ufw reload
```

### 4. 云厂商安全组（最常漏的一步）
登录云控制台（腾讯云/阿里云/华为云）→ 云服务器 → **安全组**：
1. 找到该实例关联的安全组 → 入方向规则 → 添加规则：
   - 协议：**TCP**；端口：**9000**（或 `1-65535` 省事）；来源：`0.0.0.0/0`；策略：允许；
2. 确认实例**确实关联**了这个安全组；
3. 确认你用的是**公网 IP**（弹性公网 IP / 公网 IP），不是内网 IP。

### 5. 从外部验证端口通不通
在**另一台电脑/手机**（别用服务器本机）：
```bash
telnet 你的公网IP 9000
# 或在线工具：https://ping.pe  → 填 你的IP:9000 点 ping
```
连接成功说明端口已通；超时/拒绝按上面几步继续查。

### 6. 强烈建议：改用 80/443 + 域名反向代理
非常用端口（9000 等）更容易被运营商或云环境干扰。**最稳的访问方式**：
1. 宝塔 → 网站 → 添加站点（域名或 IP）→ 反向代理到 `http://127.0.0.1:9000`；
2. 云安全组只放行 `80`（HTTP）和 `443`（HTTPS）；
3. 访问 `http://你的域名` 或 `https://你的域名`（配 SSL）。

> 常见误判：宝塔「安全」放了、云安全组也放了，但 **gunicorn 绑了 127.0.0.1** 或
> **服务没启动**，从公网照样连不上——优先做第 1、2 步定位。

## 附：日志为空怎么办

新版 app.py 会同时写**文件日志** `gg_server/server.log`（不依赖宝塔面板日志）。

1. **直接查看文件日志**（最可靠）：
   ```bash
   tail -50 /www/wwwroot/gg_server/server.log
   ```
   - 有 `[gg_server] ...已启动 / Running on http://127.0.0.1:9000` → 服务正常，
     只是宝塔面板的「运行日志」标签页显示有问题（与面板版本/缓冲有关）；
   - **没有 server.log 文件** → 服务根本没启动（继续下面排查）；
   - 有启动横幅但随后 `Address already in use` → 端口被占用。

2. **看项目状态**：项目管理器项目列表里该项目是否显示「运行中」；若不是，点「启动」。

3. **确认依赖装好**：项目 → 「依赖管理」应能看到 `flask`；或服务器手动执行：
   ```
   cd /www/wwwroot/gg_server
   pip install -r requirements.txt
   ```

4. **手动命令行验证**（能立刻看到输出）：
   ```
   cd /www/wwwroot/gg_server
   python -u app.py
   ```
   终端能看到启动横幅即正常；报 `ModuleNotFoundError: flask` → 依赖没装到当前 Python；
   报 `Address already in use` → 端口被占用。

5. 宝塔面板日志在「项目设置 / 运行日志」标签页；启动命令建议加 `-u` 无缓冲。
6. 若想日志更规范，改用 gunicorn 启动（见第 10 节）。

## 附：误封申诉 / 解禁 与 OTA 更新

### 误封申诉解禁通道（v1.1.0+）
1. **被处罚用户提交**：两种方式任选
   - 打开**公开申诉页** `http://你的域名/appeal`（无需登录、不含任何后台功能，可直接
     把该链接发给群成员），填写 QQ 号 + 申诉理由提交（IP 限流 10 分钟 3 次）；
   - 或登录后台在「误封申诉 / 解禁」页提交；
2. 管理员在「已确认违规」页可直接 **标记误封解禁**，或对申诉点 **通过并解禁 / 驳回**；
3. 通过后服务端自动生成 `unban` 动作，插件下一次同步时执行
   `set_group_ban(duration=0)` **解除该用户禁言**并记录日志。

> 公开申诉页开关：`app.py` 顶部 `PUBLIC_APPEAL_OPEN`（默认 True）；设为 False 即关闭公开页。

### OTA 更新（v1.1.0+）
1. 在 `gg_server/update_source.json` 填写版本清单地址：
   ```json
   { "url": "https://你的域名/版本清单.json" }
   ```
   版本清单 JSON 格式（含版本与 zip 下载地址）：
   ```json
   { "version": "1.2.0", "notes": "新增功能", "zip_url": "https://你的域名/gg_server_1.2.0.zip" }
   ```
2. 后台「系统更新」页可 **检查更新 / 一键更新**：自动下载 zip、解压覆盖代码
   （自动备份到 `backup_时间戳/`，保留 `data/` 与 `update_source.json`）；
3. 更新完成后**手动重启服务端**生效。

> 更新包 zip 内需包含 `app.py`（顶层或任意子目录均可），版本号写在清单的 `version`。
